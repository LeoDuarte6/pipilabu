## Decision

Stop generating character geometry from primitives. That lane proved the Blender-to-Roblox mechanics, but not the required natural, soft Pipi Labu likeness. The next bounded experiment should be **Meshy 6 Multi-view Image-to-3D**, using four clean, consistent reference crops, then **Blender cleanup/rigging**, then the ordinary **Roblox 3D Importer**. Do **not** send the first candidate through Meshy's Roblox Bridge or replace the live shopkeeper.

Meshy is appropriate here because it accepts up to four views of the same object, produces GLB/FBX plus PBR maps, and explicitly recommends front + side + back + three-quarter images for a more complete result. It is a candidate generator, not a final character-art or rigging guarantee. [Meshy Multi-Image API](https://docs.meshy.ai/en/api/multi-image-to-3d) and [Meshy Image-to-3D guide](https://docs.meshy.ai/en/webapp/image-to-3d)

## The one experiment to run

Prepare four **rights-cleared, single-subject** images from the approved four-view Pipi reference: front, profile, rear, and three-quarter. Each must show the same owner in the same proportions, lighting, framing, and neutral pose; remove phone UI, scenery, other animals, lettering, and cast-shadow clutter. Meshy says a clear subject, simple background, at least 512px image, near-orthographic viewpoint, and consistent multi-view lighting reduce distortion and back-view guesswork. [Meshy input guidance](https://docs.meshy.ai/en/webapp/image-to-3d)

Generate exactly two Meshy 6 multi-view candidates from that one input set:

1. **Standard + PBR** - fidelity control; preserve the detailed face, cheeks, swallowed ear/crown silhouette, paws, and coat mass.
2. **Smart Topology + PBR** - game-mesh control; compare its topology against the Standard result rather than assuming "optimized" means attractive.

Use the web preview's cardinal views before downloading anything. Download both **GLB** (self-contained reference/material archive) and **FBX** (the Roblox export/rig working path), plus the source texture files. Meshy documents both Standard (maximum detail) and Smart Topology (game-oriented optimization), with multi-view requiring Pro or above. [Meshy Image-to-3D](https://docs.meshy.ai/en/webapp/image-to-3d) and [plan comparison](https://help.meshy.ai/en/articles/12062933-which-meshy-plan-is-right-for-you-free-vs-pro-vs-premium-vs-ultra)

### Stop / go gate - before Blender time

**Go to Blender only if one candidate passes every check:**

- All four cardinal preview views read as the same animal, not a generic upright Doge/Shiba.
- Crown is a continuous round mass with no readable triangular top ears; any ear signal is tiny, lateral, and visually swallowed.
- Face has the low eyes, soft cheek/muzzle mass, small black nose, and gentle Pipi expression at gameplay distance.
- Owner has believable counter/ground contact and compact paws; no detached face, paw, tail, or interior holes.
- It has one coherent UV/material story and no single mesh above Roblox's 20,000-triangle limit after the intended cleanup split.

**Stop and fix the four-view conditioning art instead of spending more credits** if both candidates fail the first four visual conditions. A third generation from the same bad conditioning set is not new evidence. Do not auto-rig a rejected silhouette.

The current API example reports a textured multi-image PBR result consuming **30 credits**, so the two-candidate gate is approximately **60 credits** before optional remesh/rig/animation. Treat the currently logged-in Meshy UI as the final price quote because Meshy documents feature and credit changes independently. [Meshy multi-image task example](https://docs.meshy.ai/en/api/multi-image-to-3d) and [Meshy pricing and credits](https://docs.meshy.ai/en/webapp/pricing)

## Blender: use MCP as the production assistant, not the modeler

The official Blender MCP Server exists. Blender's own Lab page describes it as a natural-language interface to Blender's Python API; Anthropic confirms the Blender developers created the connector and that it is available for Claude. [Blender Lab MCP Server](https://www.blender.org/lab/mcp-server/) and [Anthropic announcement](https://www.anthropic.com/news/claude-for-creative-work)

The installed portable Blender 4.5.10 is adequate for ordinary file work but **cannot host the official MCP server**. The official requirement is **Blender 5.1 or newer**. Exact supported setup is:

1. Install Blender 5.1+.
2. From the official Blender Lab page, drag the extension install link into Blender **twice** (first adds the Blender Lab repository; second installs the add-on), or use Blender's documented Install from Disk route.
3. Install a local MCP-capable LLM client and install/configure the MCP server using either the official `.mcpb` release bundle or the official source/setup instructions.
4. Run it only against a disposable staging `.blend` and a backed-up source folder.

The official server executes LLM-generated Python without guards and explicitly recommends a VM or non-sensitive machine. It is therefore right for mesh/UV/rig audits, material wiring, controlled cleanup scripts, repeatable export checks, and screenshot-based review - not for blindly letting an LLM sculpt taste into a character. [Blender Lab security and setup](https://www.blender.org/lab/mcp-server/)

For a live local Blender session, use Claude Desktop or Claude Code, not the browser. Anthropic's current connector documentation says local desktop extensions are available only in Claude Desktop and Claude Code; web/mobile connectors are remote and cannot reach a localhost Blender session. [Anthropic desktop vs. web connector guide](https://support.claude.com/en/articles/11725091-when-to-use-desktop-and-web-connectors)

### Blender work after the visual go

1. Import Meshy's GLB into a locked `RAW_MESHY` collection; do not edit the only source.
2. Use the source as a sculpt/reference surface. Correct crown/ear silhouette, muzzle/cheek mass, paws, ground contact, holes, self-intersections, UV seams, and material breakup in a separate `PIPI_GAME` collection.
3. Build two custom compact-animal rigs rather than scaling one mesh: an adult shopkeeper rig and a lighter child/customer rig. Each needs root/body, short spine, head, optional jaw/eyelids/cheeks, front shoulder-elbow-wrist-hand chains, rear hip-knee-ankle-toe-fan chains, plus body squash/breath controls. Weight paint manually around buried shoulders/hips, cheeks, hands, and splayed feet. Do not rely on Meshy's humanoid-oriented API rig.
4. Make a neutral Roblox-validation render in Blender using the actual PBR maps; a beauty render with unavailable shader tricks is not a pass.
5. Export base mesh/rig as FBX; export each action (`Idle`, `Talk`, `Serve`, `Happy`, `Stressed`, and later walk/leave) as a **separate** FBX.

## Roblox-ready contract

The candidate stays an NPC Model, not an avatar body. Roblox supports FBX/GLTF with multiple mesh objects, PBR, rigs, skinning, animation data, and vertex colors. Each individual mesh must be watertight, have volume, and remain at or below 20,000 triangles. Bone transforms must be frozen; root at `(0,0,0)`; each vertex may have at most four bone influences; the root bone must have no skin weights. [Roblox importer](https://create.roblox.com/docs/studio/importer) and [Roblox mesh/rig specifications](https://create.roblox.com/docs/art/modeling/specifications)

For Blender FBX export: `Path Mode = Copy`, `Embed Textures = on`, `Apply Scalings = FBX Unit Scale`, `Add Leaf Bones = off`, and `Bake Animation = off` on the base character. Roblox permits one animation track per model export, hence action-per-FBX. [Roblox export settings](https://create.roblox.com/docs/art/modeling/export-requirements) and [animation specification](https://create.roblox.com/docs/art/modeling/specifications)

Use SurfaceAppearance for the baked color, normal, roughness, metalness, and optional emissive maps. The normal map must be **OpenGL tangent-space**; Roblox's PBR doc explicitly rejects other normal formats. Preserve stable object names and PBR filename suffixes (`_Color`, `_Normal`, `_Rough`, `_Metal`) so Studio Reimport can update the candidate without discarding Roblox-specific settings. [Roblox PBR textures](https://create.roblox.com/docs/art/modeling/surface-appearance) and [Roblox reimport](https://create.roblox.com/docs/art/modeling/reimport)

Only after these Blender gates pass should we use Studio's 3D Importer into an isolated private review Model, compare in neutral and market lighting, and let Leo/Jon make the taste decision. No new import alters the active owner until that review is explicitly approved.
